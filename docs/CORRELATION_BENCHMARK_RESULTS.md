# CASEPULSE synthetic correlation benchmark

**Fixture:** `correlation-synthetic-v1` (`tests/fixtures/correlation-benchmark-v1.ts`)  
**Baseline measured:** 2026-10-24  
**Detector policy:** name Jaccard threshold 0.75 inclusive; 60 elapsed-day window; score threshold 75 changes only the suggested action.

## Benchmark definition

The fixture has 36 manually specified, synthetic case pairs with expected institution identity, related-incident, and potential-duplicate labels plus a rationale for each pair. No real complainant or institution personal data is used.

Candidate ground truth is **same institution across different bureaus**. An emitted candidate is a true positive when this label is true and a false positive when it is false. A missed expected cross-bureau same-institution pair is a false negative. Same-bureau pairs are negative for the cross-bureau candidate task. This evaluates entity candidate generation; it does not claim to evaluate incident or duplicate classification.

The baseline called the production detector unchanged. A thrown error after candidate selection was counted as an accepted candidate for the confusion matrix and separately reported as an execution error; this applied only to `ADVERSARIAL-01`, which was accepted due to equal empty names and then threw while serializing an invalid filing date.

## What is being measured

The detector compares every distinct cross-bureau pair. A candidate is generated by a matching truthy AISHE value after trimming/case normalization, an exact AICTE permanent ID, an exact nonempty trimmed institution-name string (case-insensitive), or normalized institution-name token Jaccard similarity at least 0.75. Institution IDs are used to load institution master data; equality of `institutionId` alone is not a candidate-generation condition. State/district, category, and filing-time proximity contribute evidence or score only; they do not generate or reject candidates. Complaint title and description are not read by the detector.

The name boundary is inclusive: the exact 0.75 fixture case is accepted and its `institution_name` evidence is a match. A just-above case is accepted. The below-boundary case emits no candidate, so there is no evidence record for that pair. The 60-day temporal evidence/score boundary is separately covered by the existing unit test and is inclusive; temporal proximity does not affect candidate generation.

The detector does not return `relationshipKind` classifications. The two fixture pairs labelled as potential duplicate complaints both produce institution candidates but receive no duplicate classification; the explicitly non-duplicate same-institution case also receives no duplicate classification. Consequently duplicate precision/recall are **not applicable**: no duplicate classifier exists to score. The same limitation applies to related-incident labels. Shared identifiers establish only an entity match and are not duplicate evidence.

## Limitations and decision

This is a small, deliberately constructed synthetic regression fixture, not a random sample of production complaints. Its precision, recall, and F1 do not estimate real-world accuracy or generalize to actual institutions, bureau data quality, name distributions, or complaint prevalence. Category and duplicate labels are scenario annotations; the current engine has no complaint-text similarity, complainant/event identity, address/campus resolution, or incident classifier with which to evaluate them. Invalid or missing dates no longer crash detection: they disable temporal evidence and bonus, produce an explicit evidence/reason note, and yield an empty `flaggedDate` only when neither side has a valid date.

The 0.75 name-similarity threshold and 60-day temporal window are unchanged. The behavior change rejects only empty/whitespace-only exact names and safely handles invalid dates. The remaining errors support further investigation of generic-name collisions, registry coverage, and campus-aware resolution, but selecting more policy changes requires additional labeled examples and explicit operational trade-offs. In particular, geography should not automatically reject same-name campuses, and institution identity must not be converted into a duplicate-complaint claim.
